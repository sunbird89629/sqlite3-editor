# Proposal

## Why

数据表只能按自然顺序逐页浏览，无法按列排序、筛选或直接跳到某一页，定位一条记录往往要连点几十次「Next」。顶部的 Custom 查询框在失焦时立即执行，输入长 SQL 时几乎必然误触发；它还与 More actions 里的可写「Custom Query」同名不同义，容易让人在以为是只读的地方提交写操作。

## What Changes

- 数据表与查询结果可按列排序（升序 / 降序 / 清除），可按关键字筛选，可输入页码跳转。排序与筛选由数据库执行，作用于完整结果而不是当前页。
- 分页控件显示可编辑的当前页码和总页数；每页仍固定 10 条（不变）。
- 顶部「Custom」复选框改为「Table / Custom query」模式开关；两种模式互斥，切换时显示当前模式。
- 查询只在点击「Run query」或按 Ctrl+Enter 时执行；输入框旁给出只读提示。
- 离开查询模式时，若草稿尚未执行，先确认；无论选择哪项，草稿都保留。
- 查询失败时在输入框下方显示错误，并保留上次成功的结果；查询为空时显示空状态和示例查询。
- `Auto reload` 与原来的 Tools 菜单并入 More actions；移除 More actions 里重复的 Custom Query 入口，可写查询只经 SQL Editor 进入。
- 表头单击改为排序；列的重命名、删除、添加和隐藏移到表头右键菜单；列可见性只在 `SELECT` 后面的列列表中修改。
- 数据区显示记录数、当前排序、筛选状态，以及检测到外部修改时的重新载入提示。
- 删除两处重复的分区标题。

## Capabilities

### New Capabilities

- `viewer-query-mode`: 只读自定义查询模式的进入、执行、草稿保留与错误处理，以及表格模式与查询模式之间的切换。

### Modified Capabilities

- `data-grid-pagination`: 新增排序、筛选和页码跳转要求；分页控件由只读页码改为可编辑页码输入。

## Impact

- 主要影响 `ui/table.tsx`（查询构建、排序与筛选状态、表头与分页控件）、`ui/main.tsx`（工具栏、查询模式、数据区 meta）和 `ui/style.scss`。
- 查看器的取数与计数语句新增 `ORDER BY` 与参数化的 `WHERE`；按行排序时的 rowid 锚点优化仅在自然顺序下启用。
- 不需要数据库结构变更，也不新增依赖。
- 本变更的行为已在提交 `88637ba`（排序、筛选、跳页）和 `986152b`（工具栏与查询模式）中实现；此记录用于补齐规格与验证轨迹。
