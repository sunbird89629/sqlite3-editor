# Design

## Context

查看器用请求代次（`reloadGeneration`）避免旧请求覆盖新结果，但没有任何"正在取数"的状态对外暴露；失败时只设置 `invalidQuery`，已取回的行继续显示；自动刷新由 `useInterval` 每秒检查 `reloadRequired`，不检查编辑器是否包含未保存内容。见 proposal.md - Why。

## Goals / Non-Goals

**Goals:** 让取数与失败状态可见、可阻止重复请求；让自动刷新不与未保存编辑冲突；保持菜单命令不绕过显式执行。

**Non-Goals:** 请求取消、进度百分比、并行请求合并、跨重载的草稿持久化。

## Decisions

1. **加载标记用布尔量，并由请求代次收尾。** `reloadTable` 开始时置 `viewerLoading: true`，在 `finally` 中仅当本次代次仍是最新时清除。这样快速连续翻页时，旧请求结束不会提前收起指示器。备选是计数器，但没有额外表达力。
2. **骨架行只在没有可显示行时使用**，已有行时改为降低不透明度并保留内容。这样避免每次翻页都闪烁成空白，同时让首次取数不再是纯白区域。
3. **失败标记由"是否仍有行"推导**：捕获错误时若 `records.length > 0` 就置 `viewerStale`，成功取数任意路径都清除。这样不需要在 UI 里推断错误与数据是否匹配。
4. **隐藏排序列时在 store 层清除排序**，`setVisibleColumns` 一处处理，覆盖列列表浮层和表头右键两条入口，避免两处逻辑分叉。
5. **自动刷新在存在未保存编辑时直接跳过**，`reloadRequired` 保持为真，因此提示条持续可见；编辑结束后下一个 tick 自然刷新。选择跳过而不是排队等待，是为了复用现有每秒检查，不引入额外订阅。
6. **菜单命令通过 `pendingQuery` 传递语句**：菜单把语句写进 store，界面读取后填入编辑器并清空该字段，随后走正常的模式切换。这样不把草稿塞进 `customViewerQuery`，避免"填充即执行"。
7. **Schema 视图下隐藏 meta 行**，因为该行描述的是数据网格的记录数、排序和筛选，在结构视图中没有意义。

## Risks / Trade-offs

- [加载标记与自动刷新叠加时可能闪现] → 指示器只由最新代次关闭，并且骨架行只在无数据时出现，正常路径下只在真正取数期间可见。
- [跳过自动刷新会让提示条常驻] → 这正是期望行为；提示条同时提供手动 Reload。
- [骨架行不是真实列宽] → 使用跨列的单行占位，接受与真实列宽不一致。
- [Seed 语句依赖本地界面状态] → 只在当前窗口有效，不写入持久化状态，与既有草稿策略一致。

## Migration Plan

无数据库迁移，无配置变化。回滚应用版本即可恢复旧行为。
