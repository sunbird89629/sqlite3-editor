# Design

## Context

`ui/table.tsx` 用 `visibleAreaTop`、`visibleAreaSize`、记录数及 LIMIT/OFFSET 管理虚拟窗口，并在可用时使用 rowid 锚点；滚轮和自定义纵向滚动条修改窗口。`ui/main.tsx` 的拖动手柄和持久化设置会改变窗口大小。现有切换窗口通过编辑器的 `beforeUnmount` 保护未提交内容，异步查询有 generation 防止旧结果覆盖。

## Goals / Non-Goals

**Goals:** 固定每页 10 条，复用按需查询和现有编辑保护，处理查询切换、结果变化及异步竞态。

**Non-Goals:** 修改数据库格式、原生 SQL Editor 的独立查询结果、排序语义，或引入可配置页大小。

## Decisions

1. 以 bigint 页偏移管理数据，大小固定 10；页数和末页偏移使用整数运算，避免将大型记录数转换为不安全的 JavaScript number。每次查询最多获取一页，保留可安全复用的 rowid 锚点优化；不一次加载全部记录，以免大表内存增长。
2. 在数据表附近提供上一页、页码和下一页；移除表格纵向滚动事件、滚动条以及改变页大小的拖动手柄，忽略旧的 `visibleAreaSize` 持久化值。保留横向滚动，页面整体可按原有方式滚动。
3. 翻页经现有编辑确认路径，确认成功后再更新偏移；取消时不改变页码或记录。切表、查询变更重置偏移；计数刷新时按最后有效页对齐偏移，空表设为 0。保留查询 generation 保护，避免快速翻页或自动刷新造成结果错位。
4. 保留表格空行或插入入口所需的既有交互，但它们不计入 10 条记录；检查行选择、插入和编辑定位在翻页后仍对应正确记录。

## Risks / Trade-offs

- [大偏移查询可能较慢，尤其自定义查询或无 rowid 表] → 保持现有按需 LIMIT/OFFSET 与安全的锚点优化；不承诺任意页跳转性能。
- [刷新或编辑期间计数变化可能造成页码与数据暂时不同步] → 统一钳制页码并沿用请求代次保护，测试快速切页及末页删除。
- [既有测试依赖滚动或可变窗口] → 更新相关回归测试，验证替代行为及既有编辑交互。

## Migration Plan

升级后直接忽略旧行数设置，无数据库迁移；回滚应用版本即可恢复原有滚动行为。
