# Design

## Context

查看器把表名或自定义查询包成子查询，用 `LIMIT/OFFSET` 取当前页，并用 `COUNT(*)` 算总页数；向上翻页时若可用 rowid，则改用 `WHERE rowid > ?` 锚点避免大偏移。请求有 generation 号保护，过期结果会被丢弃。翻页、切表等操作经 `remote.guardInsertEditor()` 与编辑器的 `beforeUnmount()` 处理未保存内容。见 proposal.md - Why。

## Goals / Non-Goals

**Goals:** 排序与筛选对完整结果生效；页码可直达；模式与入口职责清晰；查询草稿不因模式切换或失败而丢失。

**Non-Goals:** 可配置页大小；把草稿持久化到 webview 重载之后；改动编辑器（底部表单）的交互；服务端分页协议或数据库结构变更。

## Decisions

1. **排序与筛选下发到 SQL。** 备选是只对已取回的 10 行做前端排序，实现更小，但翻页后顺序会"重置"、筛选也只筛当前页，用户会据此得出错误结论。因此拼进 `ORDER BY` / `WHERE`，关键字用参数绑定，`COUNT(*)` 复用同一筛选条件。
2. **按列排序时追加 rowid 作为第二排序键，并关闭锚点优化。** 锚点只在升序 rowid 时成立。默认（自然顺序）继续走锚点，大表向上翻页仍然快；一旦用户按其它列排序，改用 `OFFSET`，接受大偏移变慢，换取顺序正确。
3. **筛选用 `CAST(col AS TEXT) LIKE ? ESCAPE '\'`，并转义 `%` 与 `_`。** 这样数值和 BLOB 列也能被文本匹配，同时用户输入里的通配符按字面处理。筛选覆盖结果的每一列，包括被隐藏的列。
4. **排序和筛选走与翻页相同的守卫。** 先 `guardInsertEditor()` 与 `beforeUnmount()`，通过后才改 store 并重新取数；取消时不改页码、排序和筛选，UI 草稿回退到 store 的值。
5. **页码输入用本地草稿，回车或失焦时提交。** 如果直接把输入框绑定到 store，每按一次键都会重新取数。越界值在提交时夹取到 `1..总页数`。
6. **草稿放在组件本地状态，执行时才写入 `customViewerQuery`。** 执行前去掉末尾分号，避免子查询包装后语法错误。离开查询模式时用 `<dialog>` 询问，但两个选项都保留草稿；草稿不写入持久化状态，重载窗口后清空（非目标中已说明）。
7. **只读做两层。** 客户端先拒绝非 `SELECT`/`WITH` 语句以获得即时反馈；数据库侧仍使用只读连接，任何绕过前端校验的写入都会被拒绝。
8. **错误与空状态分家。** `invalidQuery` 只作为提示，不再让表格整体早退；空表名与空查询由 `clearViewer()` 归零记录并把数据区交给空状态渲染，避免显示上一次的表数据。
9. **表头单击排序，列操作进右键菜单。** 原来单击表头会打开 ALTER 表单，与"点表头排序"的通用预期冲突。拖拽列宽时用 ref 抑制随后触发的 click，避免调整宽度顺带排序。
10. **合并工具栏入口。** `Auto reload` 属低频设置、Tools 菜单属低频操作，一并收进 More actions；删除 More actions 里可写的 Custom Query，只读查询统一由模式开关进入，可写 SQL 只有 SQL Editor 一条路径。

## Risks / Trade-offs

- [按列排序后大偏移查询变慢] → 默认顺序仍走 rowid 锚点；不在规格中承诺任意排序下的跳页性能。
- [复杂查询每次筛选都重算 `COUNT(*)`] → 沿用现有计数路径并在界面上提示"复杂查询计数可能较慢"；后续可改为先取 `LIMIT n+1` 判断是否还有下一页。
- [排序/筛选打断正在编辑的单元格] → 统一走既有确认对话框，取消即等于放弃这次排序或筛选。
- [列操作移入右键后不易发现] → `SELECT` 后面的列列表仍是可见性的主入口，右键菜单保留重命名、删除、添加列。
- [查询草稿不跨窗口存活] → 规格只要求跨模式切换保留；持久化留作后续变更。

## Migration Plan

无数据库迁移。升级后失焦执行与表头 ALTER 的旧行为消失，用户可从表头右键菜单完成同样的列操作；回滚应用版本即可恢复旧行为。
