# Design

## Context

单元格点击当前直接进入 `UPDATE` 编辑器并挂载就地输入框；键盘导航只在 `UPDATE` 状态下移动正在编辑的单元格；编辑面板没有折叠概念；值类型用五个 `Checkbox` 模拟单选；原生 SQL 结果渲染在页面末尾。见 proposal.md - Why。

## Goals / Non-Goals

**Goals:** 让选中状态可见且可键盘操作；把"编辑"变成显式动作；给编辑面板一个可收起的形态；让写入成功有确认。

**Non-Goals:** 多单元格范围选择、复制选区、撤销历史、跨窗口保存折叠状态、把就地输入框换成独立编辑器。

## Decisions

1. **选中状态放在查看器 store 的 `selectedCell`**，与编辑器的 `statement` 分开。选中不产生任何写入语义，重新取数或切表即清空。
2. **点击行为两段式**：未选中 → 选中并聚焦；已选中 → 进入编辑。进入编辑仍走 `beforeUnmount()`，因此未保存内容仍会被询问。双击与 Enter/F2 走同一入口，避免两套逻辑。
3. **键盘导航放在 `keybindings.ts`**，只在没有文本焦点、未处于编辑状态且存在选中单元格时生效；到达页边界时调用 `setPaging` 换页，再在新页上保持行列位置。
4. **单元格 `tabIndex` 只在被选中时为 0**，形成 roving tabindex；点击时主动聚焦，键盘移动后重新聚焦新单元格，保证连续按键仍落在表格上。
5. **折叠与反馈状态放在查看器 store**（`editorCollapsed`、`editorStatus`），避免改动编辑器 store 的联合类型；每个编辑动作开始时展开，`cancel()` 结束时收起。
6. **保存反馈用 `aria-live="polite"` 而不是 `role="status"`**，因为编辑面板内已有 `role="status"` 的状态点，两个同名角色会让辅助技术与测试都难以区分。
7. **值类型改为原生单选组**，每组用独立的 `name`（INSERT 按列编号、UPDATE 固定），避免多列之间互相取消选中。
8. **结果面板移到数据区 meta 行下方**，因为它描述的是刚执行语句的输出，而不是页面级通知；复制使用剪贴板 API，CSV 按 RFC 4180 转义引号。

## Risks / Trade-offs

- [两段式点击增加一次点击] → 双击、Enter、F2 与再次点击都能进入编辑；测试与习惯说明同步更新。
- [折叠面板可能让用户找不到编辑入口] → 标题栏始终显示当前语句与折叠控件，任何新的编辑动作都会自动展开。
- [跨页键盘移动依赖异步取数] → 换页后重新读取 store 再设置选中，避免使用过期记录。
- [复制大结果到剪贴板可能耗时] → 结果本身已有 500 行上限。

## Migration Plan

无数据库或配置迁移。回滚应用版本即可恢复单击编辑与常驻面板。
